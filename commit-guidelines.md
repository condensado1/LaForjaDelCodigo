# Guía de commits

Usamos **Conventional Commits** para mantener historial claro y fácil de revisar.

## Formato

`tipo: descripción corta en infinitivo`

Tipos recomendados:
- `feat:` nueva funcionalidad
- `fix:` corrección de bug
- `docs:` cambios en documentación
- `chore:` tareas de mantenimiento
- `refactor:` cambios internos sin alterar comportamiento esperado
- `test:` cambios o creación de pruebas

## Ejemplos correctos

- `feat: agregar endpoint de registro`
- `fix: corregir validación de correo duplicado`
- `docs: actualizar pasos de instalación en README`
- `test: añadir pruebas para módulo de autenticación`

## Ejemplos incorrectos

- `arreglos varios`
- `update stuff`
